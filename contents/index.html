webserv

This page is served by the server it tests. Run sends the request from your browser and compares the status code; Open shows the real page, so you can check it in the Network tab.

Start (from the repository root)make && ./webserv
Same, explicit config./webserv config/default.config

Configuration: config/default.config. Website 1 is this tester on 0.0.0.0:8080; website 2 is on 127.0.0.1:8081.

Basic checks

GET, POST and DELETE work, an unknown method does not crash the server, and every answer has the right status code.

  • GETA static file.
    200
  • POSTA body sent to a CGI script, which echoes it back.
    200
  • POST where it is not allowed/ is GET-only.
    405
  • UNKNOWN methodFOO /: answered with 501, and the server keeps running.
    501
  • Unimplemented methodPUT /: only GET, POST and DELETE are implemented.
    501
  • DELETECreates, deletes and re-checks a file in /uploads.
    201 → 204 → 404
  • Upload files and retrieve themUpload from the browser, open each stored file, delete it. Files are stored byte-for-byte in ./contents/uploads.
    201
    Open uploads
Telnet / nc: a raw requestprintf 'GET / HTTP/1.1\r\nHost: localhost\r\n\r\n' | nc 127.0.0.1 8080
curl: upload a file, fetch it back, delete itcurl -i -F "file=@README.md" http://127.0.0.1:8080/uploads && curl http://127.0.0.1:8080/uploads/README.md && curl -i -X DELETE http://127.0.0.1:8080/uploads/README.md

CGI

.py runs through /usr/bin/python3 and .sh through /bin/bash. Scripts live in ./contents/cgi and run with that directory as their working directory.

  • GET with a query stringThe script receives QUERY_STRING.
    200
    Open
  • POST with a bodyThe body arrives on the script's stdin; the script ends at EOF.
    200
  • Correct directory for relative pathsThe script opens context.txt by a relative path and prints the environment it received. Look for RELATIVE_FILE=CGI working directory is correct.
    200
  • Script that crashescrash.py raises an exception before printing a header.
    502
    Open
  • Script with invalid outputOutput without a CGI header block is rejected.
    502
  • Infinite looploop.py never ends. After 15 s the server kills it and answers 502. Meanwhile, the rest of this page keeps working: try another check.
    502 after ~15 s
  • Missing scriptA .py path that does not exist.
    502
Chunked request: the server un-chunks it, and the CGI gets a plain body ending in EOFcurl -i -H "Transfer-Encoding: chunked" -d "chunked body" "http://127.0.0.1:8080/cgi/test.py?context"

Port issues

Different ports serve different websites; the same interface:port twice is an error, because virtual hosts are not implemented.

Runtime contract and current boundaries

Where to look when the evaluation sheet asks for the code. Everything below is in srcs/.

QuestionAnswer
Event mechanismOne poll() in Worker::run(), through Poller. It watches listeners, clients and CGI pipes, for reading and for writing.
From poll() to client I/OWorker::dispatchEvent() → acceptNew(), onReadable(), onWritable(), onCgiReadable(), onCgiWritable(). One read or write per readiness event.
Return values<= 0 on a client socket closes the client; on a CGI pipe, < 0 fails the job and 0 means EOF. errno is never checked after read/write.
Disk filesOpened in StaticFile and streamed in 64 KiB chunks from Worker::refillFromBodyFile(), only when the client socket is writable.
forkOnly in Cgi::start().
TimeoutsIdle clients: 30 s. CGI: 15 s without pipe I/O (120 s at most), then SIGTERM, then SIGKILL.
No relinkingRun make twice: the second run prints Nothing to be done.
